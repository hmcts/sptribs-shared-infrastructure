# sptribs-shared-infrastructure

Terraform for the Azure resources shared by the Special Tribunals applications: [sptribs-case-api](https://github.com/hmcts/sptribs-case-api), [sptribs-frontend](https://github.com/hmcts/sptribs-frontend) and [sptribs-dss-update-case-web](https://github.com/hmcts/sptribs-dss-update-case-web).

This repository contains infrastructure only. It does not build or deploy any application.

## What's provisioned

Each environment gets one resource group, `sptribs-<env>`, which holds the resources below.

| Resource | Name | File |
|---|---|---|
| Resource group | `sptribs-<env>` | [`main.tf`](main.tf) |
| Application Insights | `sptribs-appinsights` | [`tf-app-insights.tf`](tf-app-insights.tf) |
| Application Insights for preview (AAT run only) | `sptribs-appinsights`, environment `preview` | [`tf-app-insights.tf`](tf-app-insights.tf) |
| Key Vault | `sptribs-<env>` | [`tf-key-vault.tf`](tf-key-vault.tf) |
| PostgreSQL flexible server | `sptribs-<env>-flexible-db-v15` | [`postgres.tf`](postgres.tf) |
| Service Bus topic authorisation rule | `sptribs-sendonly` on CCD's `ccd-case-events-<env>` topic | [`servicebus.tf`](servicebus.tf) |
| Action group and metric alert | `sptribs-ag1`, `exceptions_alert` | [`tf-app-insights-alerts.tf`](tf-app-insights-alerts.tf) |

### Application Insights

[`tf-app-insights.tf`](tf-app-insights.tf) uses the [terraform-module-application-insights](https://github.com/hmcts/terraform-module-application-insights) module to create `sptribs-appinsights`. The applications send telemetry to it using the connection string from Key Vault.

The AAT run also creates a second instance with environment `preview`, which preview (pull request) deployments use.

### Key Vault

[`tf-key-vault.tf`](tf-key-vault.tf) uses the [cnp-module-key-vault](https://github.com/hmcts/cnp-module-key-vault) module to create the `sptribs-<env>` vault. All three applications mount secrets from this vault through their Helm charts.

Access is granted to:

- the `DTS Special Tribunals` Entra group (`product_group_name`);
- the Jenkins identities, so the pipelines can read and write secrets;
- the preview Jenkins identity, in AAT only (`grant_preview_jenkins_access`);
- the `sptribs` managed identity, which the module creates (`create_managed_identity = true`) and the application pods use.

The provider sets `purge_soft_delete_on_destroy = true`, so destroying the vault purges it permanently.

### Secrets written to the vault

Terraform writes these secrets. Some are generated by resources in this repository and some are copied from another team's vault.

| Secret | Source | Environments |
|---|---|---|
| `app-insights-instrumentation-key`, `app-insights-connection-string` | `sptribs-appinsights` | All except ITHC |
| `app-insights-instrumentation-key-preview`, `app-insights-connection-string-preview` | The preview Application Insights instance | AAT only |
| `s2s-case-api-secret` | `microservicekey-sptribs-case-api` in vault `s2s-<env>` (resource group `rpe-service-auth-provider-<env>`) | All except ITHC |
| `ccd-importer-username`, `ccd-importer-password` | `ccd-importer-username` and `ccd-importer-password` in vault `civil-<env>` (resource group `civil-service-<env>`) | All except ITHC |
| `docmosis-access-key` | `docmosis-access-key` in vault `em-stitching-<env>` (resource group `em-stitching-<env>`) | All |
| `sptribs-POSTGRES-USER`, `sptribs-POSTGRES-PASS` | The admin credentials generated for the PostgreSQL flexible server | All |
| `ccd-case-events-sendonly-connection-string` | The primary connection string of the `sptribs-sendonly` rule | All |

The copied secrets are read with Terraform `data` sources, so the upstream vault and secret must exist before an apply can succeed.

The applications read other secrets from the same vault that this repository does not manage, for example the GOV.UK Notify API key, IDAM client secrets and the remaining Postgres connection settings (`sptribs-POSTGRES-HOST`, `-PORT` and `-DATABASE`).

### PostgreSQL

[`postgres.tf`](postgres.tf) uses the [terraform-module-postgresql-flexible](https://github.com/hmcts/terraform-module-postgresql-flexible) module.

| Setting | Value |
|---|---|
| Server | `sptribs-<env>-flexible-db-v15` (the `v15` suffix is part of the name; the server runs PostgreSQL 16) |
| Database | `sptribs` |
| Schemas with reader access | `public` (the case API's own tables, managed by Flyway) and `ccd` (the CCD case tables for this case type) |
| SKU | `var.pgsql_sku`, default `GP_Standard_D2ds_v4` |
| Storage | `var.pgsql_storage_mb`, default 65536 MB, with auto-grow on |
| Geo-redundant backups | `var.postgres_geo_redundant_backups`, default `false`, `true` in prod |
| Extensions | `pg_stat_statements`, `pg_buffercache` |
| Server parameters | `log_lock_waits`, Query Store and wait sampling capture (`ALL`), log file download with 7-day retention |
| Subnet | The `expanded` subnet (`subnet_suffix`) |

The Jenkins identity is set as an Entra admin of the server (`admin_user_object_id`). The generated admin login and password are written to Key Vault as `sptribs-POSTGRES-USER` and `sptribs-POSTGRES-PASS`.

The module uses the `azurerm.postgres_network` provider alias from [`main.tf`](main.tf), which targets the AKS subscription (`var.aks_subscription_id`), for the server's network resources.

### Service Bus send-only rule

The Service Bus namespace and topic belong to CCD. [`servicebus.tf`](servicebus.tf) looks up namespace `ccd-servicebus-<env>` and topic `ccd-case-events-<env>` in resource group `ccd-shared-<env>`, then creates a topic authorisation rule, `sptribs-sendonly`, with send permission only (no listen or manage).

The rule's primary connection string is written to Key Vault as `ccd-case-events-sendonly-connection-string`. The case API uses it to publish case events to the topic for Work Allocation.

### Alerts

[`tf-app-insights-alerts.tf`](tf-app-insights-alerts.tf) defines:

- an action group, `sptribs-ag1` (short name `spt-alerts`), with an email receiver and a webhook that uses the common alert schema;
- a metric alert, `exceptions_alert`, on `sptribs-appinsights`. It fires when the maximum of `performanceCounters/exceptionsPerSecond` is 2 or more, and notifies the action group.

The metric alert is created only when `custom_alerts_enabled` is `true`.

## Environments

The pipeline passes the environment name and other platform values (`env`, `tenant_id`, `jenkins_AAD_objectId`, `aks_subscription_id`, `component` and `common_tags`). Per-environment overrides are in `<env>.tfvars`:

| Environment | File | Overrides |
|---|---|---|
| AAT | [`aat.tfvars`](aat.tfvars) | `custom_alerts_enabled = "true"` |
| Demo | [`demo.tfvars`](demo.tfvars) | `custom_alerts_enabled = "true"` |
| Perftest | [`perftest.tfvars`](perftest.tfvars) | `custom_alerts_enabled = "true"` |
| Prod | [`prod.tfvars`](prod.tfvars) | `custom_alerts_enabled = "true"`, `postgres_geo_redundant_backups = true` |
| ITHC | none | Uses the defaults in [`variables.tf`](variables.tf) |

Defaults for every other variable are in [`variables.tf`](variables.tf). Remote state uses the `azurerm` backend ([`state.tf`](state.tf)), which the pipeline configures. The Terraform version is pinned in [`.terraform-version`](.terraform-version), and the provider versions in [`state.tf`](state.tf).

## Pipeline

[`Jenkinsfile_CNP`](Jenkinsfile_CNP) runs the HMCTS [cnp-jenkins-library](https://github.com/hmcts/cnp-jenkins-library) `withInfraPipeline` for product `sptribs`. Build notifications go to the `#special-tribunals-builds` Slack channel.

| Build | What runs |
|---|---|
| Pull request | `terraform plan` against AAT, and a second plan against prod. For a PR that targets `demo`, `perftest` or `ithc`, the second plan runs against that environment instead. The `not-plan-on-prod` label skips the second plan. |
| Merge to `master` | `terraform apply` to AAT, then to prod. `syncBranchesWithMaster` then pushes `master` to the `demo`, `perftest` and `ithc` branches. |
| Build of `demo`, `perftest` or `ithc` | `terraform apply` to that environment. These builds are started by the branch sync. |

Dependencies, including module and provider versions and the Jenkins library, are updated by Renovate ([`renovate.json`](renovate.json)).

## Making a change safely

1. Branch from an up-to-date `master`.
2. Edit the `.tf` files. Put anything that differs between environments in a variable with a default in [`variables.tf`](variables.tf), and override it in the `<env>.tfvars` files. Remember that ITHC has no tfvars file and always takes the defaults.
3. Use `count` on `var.env` for resources or secrets that should exist only in some environments, following the existing pattern (for example `count = var.env == "aat" ? 1 : 0`).
4. Format and validate locally:

   ```bash
   terraform fmt
   terraform init -backend=false
   terraform validate
   ```

   `terraform init` needs SSH access to GitHub, because the modules are fetched with `git@github.com:` sources.
5. Raise a pull request and read both plans in the Jenkins output before asking for review. Check in particular for:
   - any resource that will be destroyed or replaced, especially the Key Vault, the PostgreSQL server or its database;
   - changes to secret values that the running applications depend on.
6. When you rename or move a resource, add a `moved` block (see [`tf-app-insights.tf`](tf-app-insights.tf) for examples) so Terraform does not destroy and recreate it.
7. When you copy a new secret from another team's vault, confirm that the vault and secret exist in every environment the resource applies to, including ITHC, before you merge.
8. Merging applies to AAT and then prod in the same build. Make sure the change is ready for prod when you merge.

After the apply, check that the applications still start and can read their secrets.

## What isn't here

- **Applications and their Helm releases.** Each application repository has its own chart and pipeline, and the environment-specific Flux configuration is in [hmcts/cnp-flux-config](https://github.com/hmcts/cnp-flux-config).
- **Preview databases and Service Bus.** Preview deployments use a shared preview PostgreSQL server and resources declared in the preview overlay in [hmcts/cnp-flux-config](https://github.com/hmcts/cnp-flux-config).
- **The Service Bus namespace and topic.** These belong to CCD. This repository only adds the send-only rule.
- **Redis for the citizen frontend.** It is defined in the `infrastructure/` directory of [hmcts/sptribs-frontend](https://github.com/hmcts/sptribs-frontend).
- **Secrets not listed above.** Values such as the GOV.UK Notify key, IDAM client secrets and the remaining Postgres connection settings are set in the vault outside this repository.
- **The CCD case-type definition.** It is generated by [hmcts/sptribs-case-api](https://github.com/hmcts/sptribs-case-api) and imported by that repository's pipeline.
- **Upstream secrets.** The S2S key, the CCD importer credentials and the Docmosis access key are owned by the `s2s`, `civil` and `em-stitching` vaults respectively. This repository only copies them.
